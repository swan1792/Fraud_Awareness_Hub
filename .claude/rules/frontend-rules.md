# Frontend Rules

## React 19 + Vite
- No Next.js patterns. No `"use client"`, no `useRouter` from next, no `page.tsx` convention.
- Use React Router v7 for routing (`useNavigate`, `useParams`, `<Link>`, `<Routes>`).
- Vite dev server ports: client = 5173, admin = 5174.

## State Management
- Global state: Redux Toolkit store in `lib/store.js`.
- Server state: RTK Query in `lib/api.js`.
- Local state: `useState` / `useReducer` in components.
- No other state libraries (no Zustand, no Jotai, no MobX).

## Data Fetching
- ONLY through RTK Query hooks. Never `fetch()` or `axios` directly.
- All API calls go to `http://localhost:3001/api`.
- Use `useGetQuery` for reads, `useCreateMutation` / `useDeleteMutation` for writes.
- Always provide `providesTags` and `invalidatesTags` for cache management.

## Component Guidelines
- Named exports only: `export function MyComponent() {}`
- Keep components under ~200 lines
- Extract sub-components when a component grows large
- Use `useCallback` for event handlers passed to child components
- Use `useMemo` sparingly — only for expensive computations

## UI Components (shadcn)
- Located in `components/ui/`
- Generated by shadcn, do not hand-edit unless necessary
- Import from `@/components/ui/button`, `@/components/ui/card`, etc.
- Both frontends must have identical copies of UI components

## Client vs Admin Distinction
- **Client** (`frontend-client`): Read-only views, games, simulations. No CRUD.
- **Admin** (`frontend-admin`): Full CRUD for scam alerts. Dashboard layout with sidebar.
- Feature components specific to one frontend go in that frontend's `components/features/`.
